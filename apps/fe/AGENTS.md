# Frontend Development Guidelines for AI Agents

Guidelines, conventions, and architectural rules for AI assistants working on the **Ticket Box Frontend** (`apps/fe`).

---

## 🛠️ Tech Stack & Constraints

- **Framework**: Next.js 16+ (App Router with Turbopack)
- **Library**: React 19 & TypeScript 5+ (Strict Mode enabled)
- **Styling**: Tailwind CSS v4 (`@import "tailwindcss";` in `src/app/globals.css`)
- **UI System**: `shadcn/ui` (Base UI / Radix primitives, Lucide icons)
- **Fonts**: `next/font/google` with `Geist` (Sans) and `Geist_Mono` (Mono)
- **Package Manager**: Yarn Berry 4.x (`nodeLinker: node-modules`, `yarn install --immutable`)

---

## ⚡ React Server Components (RSC) vs Client Components

1. **Default to Server Components**:
   - Fetching static event data, SEO metadata generation (`generateMetadata`), initial layout skeletons must be Server Components.
   - Do NOT add `"use client"` unless the component requires:
     - React state hooks (`useState`, `useReducer`)
     - Lifecycle hooks (`useEffect`, `useCallback`)
     - Event listeners (`onClick`, `onChange`, `onSubmit`)
     - Browser-only APIs (`window`, `localStorage`, `navigator.clipboard`)

2. **Isolate Client Boundaries**:
   - Keep `"use client"` components as leaf nodes as much as possible.
   - Example: A Server Component `EventDetailPage` passes raw data into a small Client Component `<BuyTicketButton />` or `<SeatSelector />`.

## 🎨 Styling & Theming Guidelines (Tailwind CSS v4)

1. **Use Theme Variables**:
   - Always use the semantic tokens defined in `globals.css`:
     - Background: `bg-background`, `bg-card`, `bg-muted`, `bg-popover`
     - Text: `text-foreground`, `text-muted-foreground`, `text-primary`
     - Borders: `border-border`, `ring-ring`
     - Status: `bg-destructive`, `text-destructive`, `text-primary`
   - **Never hardcode arbitrary hex colors** (e.g. `bg-[#1a1a2e]`) unless strictly required for third-party brand logos.

2. **Dark Mode Compatibility**:
   - Every UI element must look crisp and legible in both light and dark modes.
   - Test contrasts using semantic classes rather than overriding with explicit `dark:...` if semantic tokens already adapt.

3. **Responsive Design**:
   - Mobile-first approach: `w-full sm:w-auto`, `grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3`.
   - Touch targets for buttons and interactive controls must be at least 44x44px on mobile (`min-h-[44px]` or `size="default"`).

## 🔌 API Client & Data Contract with Go Backend (`apps/be`)

1. **Standard Response Mapping**:
   The Go backend wraps responses in `internal/pkg/response`:
   ```typescript
   export interface ApiResponse<T> {
     code: number;
     message: string;
     data: T;
   }

   export interface PaginatedData<T> {
     items: T[];
     pagination: {
       page: number;
       page_size: number;
       total_items: number;
       total_pages: number;
     };
   }
   ```

2. **UUID v7 Entity Identifiers**:
   - Entity IDs from the Go backend (Tickets, Events, Users) are UUID v7 strings.
   - Always model them as `string` in TypeScript:
     ```typescript
     export interface Ticket {
       id: string; // UUID v7
       event_id: string;
       user_id: string;
       status: "pending" | "paid" | "cancelled" | "checked_in";
       price: number;
       created_at: string;
     }
     ```

3. **Error Handling**:
   - Handle 400 (Bad Request), 401 (Unauthorized), 404 (Not Found), 429 (Rate Limit), and 500 cleanly with Toast notifications or Alert boxes.

## 🧪 Quality & Verification Checks

Before submitting any frontend changes, verify:

1. **Build Verification**:
   ```bash
   yarn build
   ```
   Must pass with **zero TypeScript errors and zero Turbopack build errors**.

2. **Linting**:
   ```bash
   yarn lint
   ```
   Must pass with **zero ESLint warnings or errors**.

3. **Component Addition**:
   When new UI widgets are needed, install via shadcn CLI:
   ```bash
   npx -y shadcn@latest add <component-name>
   ```
   Do not rewrite standard shadcn primitives manually from scratch.

## 🔒 Security Best Practices

- **Sanitize Input**: Form validation must always be paired with schema validators like `zod`.
- **JWT Storage**: Store access tokens securely (prefer `httpOnly` secure cookies or memory; refresh tokens must never be exposed to public scripts).
- **No Secrets in Client Code**: Only prefix variables with `NEXT_PUBLIC_` if they are safe to be exposed in the browser bundle. Backend secrets, database URLs, and private API keys must never have `NEXT_PUBLIC_`.
